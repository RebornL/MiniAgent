# 会话历史的权威源是事件日志，不是消息投影

会话历史以 append-only 的事件日志落盘，模型可见的消息只是由它算出的投影（见 `CONTEXT.md` 的「投影」与「权威源」）。选择「重放」而不是「存快照」，是因为压缩与技能状态必须可重建——把它们存成快照或旁路元数据，就等于承认历史有两份真相源，而两份真相源早晚会不一致。

## Considered Options

- **存投影（消息数组）+ 旁路元数据**：实现最省，但压缩事件与技能装载事件不落盘，恢复只能靠拼装。第一版即此形态，也是本次改动的动因。
- **存定期快照（整份历史）**：恢复快，但快照之间的历史丢失；且快照本身仍是「另一种投影」，并没有解决权威源是哪一份的问题。
- **存事件日志（采用）**：恢复 = 重放；投影可随时丢弃重算；压缩产物本身成为可重放记录。

## Consequences

- 必须定义事件词汇表与格式版本，并维护相邻版本迁移链。
- 派生数据（索引、缓存）在损坏时重建即可，不做迁移。
- 恢复成本与日志长度正相关，因此需要「反向找检查点 + 正向重放」，而不是每次全量重放。
- 任何「并行存储模型可见历史」的实现都视为对本决策的偏离。
